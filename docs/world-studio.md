# Eldervale World Studio

Sign in with the existing owner account, then click **♛ World studio** at the top left or press **F8**. Ownership is checked against the authenticated account UUID in Postgres. Usernames and browser flags do not grant access. There is no browser service key or executable SQL/JavaScript console.

## Build without code

In **World**, choose a template, edit its properties and use **Place with world click**. Click terrain to commit placement; Escape cancels. For saved entities, **Select in world** or the searchable list opens editing. Move, rotate, scale, clone, delete and restore are supported. Coordinates use X and Z (world depth), in metres; heading uses degrees. Placement is immediate and saved in Supabase. Other connected clients pick up edits within about four seconds. Buildings include working doors/interiors; bank buildings and merchant NPCs open the existing services. Objects should be placed on dry, fairly level land, with doors clear of other scenery.

NPCs have dialogue, level, health, damage, seconds per attack turn, roaming radius, aggression, attackability, and respawn time. Zero roaming stays in place; zero respawn means defeated actors stay down for the current session. Persistent spawn definitions remain until explicitly deleted; combat health and defeated state are local to each client's simulation. **Preview attack** demonstrates the saved actor's attack. Peaceful NPCs still have an attack profile; enable **Can be attacked** to make one a combat opponent. Non-attackable services cannot be aggressive.

There are 11 service/human NPC templates, 13 monsters and 19 scenery/building templates. Monsters include wolf bite, deer rear kick, boar charge, bear claws, spider venom, bat swoop, golem/troll slam, wraith magic and dragon fire. Fire, venom and magic use reduced shield blocking and ignore melee armor absorption. Custom damage is the base attack contribution; the existing melee roll adds its normal random component. Death rewards retain the existing game rules.

Item templates place a persistent drop. Players collect it by clicking nearby; the server locks the drop so only one collector receives it. Grants and collected equipment are delivered to the recipient's **bank**, keeping inventory slots safe. Gold goes to the wallet. Delivery receipts are saved with the character before acknowledgment to avoid applying the same grant twice after a reconnect. World export/import provides portable JSON backups; imports add entities (up to 200 per import), and deleted entities can be restored. The world supports 2,000 active custom entities; distant actors stream out of rendering.

## Operate and moderate

**Server** configures the login welcome, ten-minute announcements, restart countdown (15–3,600 seconds), cancellation and maintenance. Restart saves progress and reloads connected clients; there is no separate authoritative game-server process to reboot. Existing inactive/browser-suspended tabs react after resuming and refreshing world state. Maintenance admits only the owner and disconnects ordinary clients. Deployment/hosting and database administration remain in GitHub/Hostinger/Supabase; the game panel cannot execute host commands or expose their credentials.

**Players** lists saved characters, their last-save times and moderation state. Give items/gold, teleport a player, kick, mute/unmute, ban/unban with a reason and duration. Offline grants arrive on next login. Kick disconnects an existing session; ban blocks shared save/chat/friend access and login until expiry. Muting is enforced on chat inserts in Postgres. Players have a **Report a player** button; reports are rate-limited and available for owner resolution. Recent chat can be removed. Last-save timestamps are not online-presence indicators.

**Audit** lists the latest 100 actions with before/after records and JSON export. Owner actions, delivery creation and world edits are transactional. Direct client writes to administrative tables are revoked and explicitly denied by RLS. The allowlisted **Terminal** accepts game commands shown by `help`; it cannot run scripts or operating-system commands.

## Research and implementation boundaries

- [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html): deny by default, validate every action, least privilege and authorization tests. Applied with private tables, authenticated RPCs, fixed owner authorization, bounded input, immutable audit writes and negative access tests.
- [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) and [database functions](https://supabase.com/docs/guides/database/functions): existing player ownership policies remain; restrictive moderation policies add to them. Privileged implementations are in a non-exposed schema with empty search paths and explicitly revoked anonymous execution.
- [RuneScape's animation-set API](https://developer.runescape.com/rs/game/config/baseanimsettype.html) and [RuneLite Actor API](https://github.com/runelite/runelite/blob/master/runelite-api/src/main/java/net/runelite/api/Actor.java): walking/running have separate animation channels. The original Eldervale rig uses separate recovery paths and combat selection; no RuneScape assets were copied. The OSRS Wiki blocked automated access; no claim is made that its original animation frames were extracted or reproduced exactly.
- [AnimSchool's run-cycle poses](https://blog.animschool.edu/2024/04/10/the-key-poses-of-a-run-cycle/) and [Toon Boom walk analysis](https://learn.toonboom.com/modules/walk-cycle-animation2/topic/walk-analysis): walking contact/passing, running recovery/flight and forward lean. Walk/run remain driven by actual distance, and sprint remains twice walk speed. A deterministic two-second motion preview is generated by `scripts/gait-motion-preview.cjs`.

The current game trusts clients for movement, combat, inventory and local NPC simulation. This update secures owner administration and shared spawn persistence; it does not turn those systems into an authoritative multiplayer combat server or prevent existing client-side inventory cheats. Shared spawn definitions are synchronized, while individual monster combat outcomes remain local. Concurrent character sessions can still overwrite ordinary character saves; use one gameplay tab per account when receiving grants.

The Supabase security advisor also reports the existing **leaked-password protection disabled** setting. [Enable that protection in Supabase Auth](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection); account-level availability depends on the project plan. This is separate from owner RPC authorization.
